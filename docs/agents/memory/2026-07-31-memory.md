## Today's Question

MemGPT and MemoryBank both assume a **retrieve-then-reason** paradigm: store records, then retrieve relevant ones at query time using static similarity search. But is this fundamental assumption limiting? What happens if memory is **dynamically reconstructed** at reasoning time rather than statically retrieved? What if the LLM itself organizes memory structures? And what if memory has gated, bounded neurocognitive mechanisms?

## Main Paper

### Metadata

- Title: Memory is Reconstructed, Not Retrieved: Graph Memory for LLM Agents
- Authors: Shuo Ji, Yibo Li, Bryan Hooi
- Year: 2026
- Venue: arXiv (2606.06036)
- Link: https://arxiv.org/abs/2606.06036

### Why this paper?

This paper directly challenges the fundamental assumption underlying MemGPT, MemoryBank, and virtually all current agent memory systems: the **retrieve-then-reason** paradigm. It proposes that memory should be **reconstructed dynamically** rather than retrieved statically — a conceptual shift that opens an entirely new design axis in the agent memory space. After Day 1 (survey/framework) and Day 2 (canonical concrete system), this is the right third paper: it introduces a competing paradigm that forces us to re-evaluate everything covered so far.

### Core Problem

Current memory-augmented agents operate on a rigid pipeline: (1) encode experience into records, (2) at query time, perform similarity search against stored records, (3) feed retrieved records into LLM reasoning. This **static retrieve-then-reason** paradigm has two fundamental limitations:

1. **No adaptive access:** The retrieval is a one-shot operation — it cannot be adapted based on intermediate reasoning results. If the agent discovers new evidence during inference that changes what information would be useful, it cannot revise its retrieval strategy.

2. **No associative reconstruction:** Human memory is not a lookup table — it is a constructive process where memory traces are actively reconstructed from interconnected cues. Current systems treat each memory as an independent record rather than as part of an interconnected, dynamically traversable graph.

### Main Idea

The paper proposes **MRAgent**, a framework built on two key innovations:

**1. Cue-Tag-Content (CTC) Graph Memory:**

Instead of flat key-value or embedding-indexed records, MRAgent represents memory as a **Cue-Tag-Content graph**:

- **Cues** are fine-grained retrieval triggers — specific words, phrases, or partial descriptions that can initiate memory access. Think of these as "entry points" into the memory space.
- **Tags** are associative bridges — semantic categories or relationship labels that connect cues to memory contents. Tags enable indirect, associative access: even if no cue directly matches a query, a chain of tags can lead to the relevant content.
- **Content** nodes store the actual memory records (natural language, facts, structured data).

The graph structure means memory is **traversable** — the agent can follow paths from one memory to another through shared tags, enabling **incidental discovery** and **serendipitous recall** that flat retrieval misses.

**2. Active Reconstruction Mechanism:**

This is the core innovation. Instead of a one-shot retrieval, MRAgent integrates LLM reasoning **directly into the memory access process**:

1. **Initial cue generation:** The LLM generates candidate cues based on the current reasoning context.
2. **Graph expansion:** The system follows edges from matching cues to tags, then from tags to content nodes, expanding the search frontier.
3. **Evidence evaluation:** At each expansion step, the LLM evaluates whether the retrieved content is relevant, contradictory, or suggestive of further exploration.
4. **Pruning and re-direction:** Based on intermediate evidence, the LLM can prune irrelevant branches and redirect the search toward more promising paths.
5. **Convergence:** The process terminates when sufficient evidence has been gathered or when the graph cannot be further expanded without combinatorial explosion.

The key technical challenge addressed is **avoiding combinatorial explosion** — unconstrained graph expansion would produce exponentially many paths. The paper's solution is **LLM-guided iterative pruning**: at each step, the LLM scores the utility of continuing each branch, and only the top-k branches are expanded further.

### Experiments/Results

- **LoCoMo (Long Conversation Memory) benchmark:** MRAgent achieves **87.3% factual recall** over 500+ turn conversations, compared to 72.1% for MemGPT and 65.4% for MemoryBank. The largest gains are on questions requiring **associative inference** (e.g., "What did Alice think about Bob's presentation after hearing Carol's feedback?"), where MRAgent outperforms by 18+ percentage points.

- **Multi-session QA:** On the **MSC (Multi-Session Chat) benchmark**, MRAgent achieves 84.2% accuracy across 10+ sessions, 3.2 points higher than MemGPT. Notably, MRAgent's advantage **grows with session count** — at session 15+, it is 7+ points higher, suggesting that graph-based reconstruction benefits from accumulated interconnections.

- **Ablation: graph structure matters more than LLM guidance.** Removing the graph structure (but keeping iterative LLM retrieval) drops performance by 14%; removing LLM guidance (but keeping the graph) drops performance by 11%. Both components are critical, but the graph structure contributes slightly more.

- **Latency:** Each reconstruction cycle takes 2-4 seconds (vs. 1-2s for MemGPT's single retrieval). The paper argues this is acceptable for non-real-time agent tasks.

### Limitations

- **Latency significantly higher than simple retrieval** — 2-4s per reconstruction vs. 1-2s per single retrieval. Not suitable for real-time conversational agents.
- **Combinatorial explosion risk remains at very large memory scales** — the paper's experiments cap at ~10K records. How the active reconstruction mechanism behaves with 100K+ records is untested.
- **The LLM-as-search-controller pattern introduces a failure mode:** if the LLM makes a bad pruning decision early in reconstruction, it may exclude the correct path permanently. The paper doesn't discuss recovery from bad pruning decisions.
- **No maintenance module:** MRAgent is focused on retrieval-time reconstruction. It inherits MemGPT's weakness of no write-time consolidation — the graph grows append-only.
- **Evaluation is limited to conversation tasks:** The paper tests on chat-based benchmarks but doesn't evaluate on agent tasks requiring procedural knowledge, tool use, or long-horizon planning.

### Modern perspective

MRAgent represents a **third paradigm** alongside MemGPT (OS paging) and MemoryBank (database update):

| System | Core metaphor | Retrieval style | Best for |
|--------|--------------|-----------------|----------|
| MemGPT | OS virtual memory | One-shot paging | Conversational recall |
| MemoryBank | Database with updates | Weighted similarity | Preference tracking |
| MRAgent | Associative graph reconstruction | Iterative LLM-guided | Complex associative inference |

The key insight: **memory representation determines what retrieval can discover**. Flat records (MemGPT) support simple recall but miss cross-record connections. Topic documents (Infini Memory) support thematic grouping but lose detail. Graph structures (MRAgent) support associative discovery but cost more at retrieval time.

This raises an architecture question: **can different memory representations coexist in a single agent?** Perhaps working memory uses flat records (fast, cheap), episodic memory uses graph structures (rich, associative), and semantic memory uses topic documents (compressed, durable).

## Related Papers

### Paper 1: A-MEM — Agentic Memory for LLM Agents

- **Authors:** Wujiang Xu, Zujie Liang, Kai Mei, Hang Gao, Juntao Tan, Yongfeng Zhang
- **Year:** 2025 (updated Oct 2025)
- **Link:** https://arxiv.org/abs/2502.12110

**Contributions:**
- Proposes a memory system where the **LLM itself organizes memory structures** dynamically, rather than using fixed schemas or embedding-based indexing.
- Inspired by the **Zettelkasten method** (a note-taking system based on atomic notes with cross-references): each memory is a structured note containing contextual description, keywords, and tags. The system automatically links new notes to relevant existing ones.
- **LLM-driven linking:** When a new memory is added, the LLM analyzes it and identifies connections to historical memories, creating bidirectional links. This is analogous to MRAgent's tag-based graph, but with LLM-guided link creation at write-time rather than LLM-guided traversal at read-time.
- The resulting memory is an **interconnected knowledge network** that grows increasingly rich as more memories are added and linked.

**Relation to main paper:** A-MEM and MRAgent share the same core insight — memory should be **structured as a graph** with associative connections — but at different timescales. A-MEM builds the graph at write-time (when a memory is stored, the LLM finds and records connections). MRAgent reconstructs the graph at read-time (when a query comes in, the LLM dynamically explores connections). This is a fundamental design axis: **write-time linking (A-MEM) vs. read-time reconstruction (MRAgent)**, with different cost profiles and different failure modes.

**Why it matters:** The write-time vs. read-time tradeoff is a recurring system design question. Write-time linking (A-MEM) is cheaper at query time but can miss connections the LLM didn't anticipate at storage time. Read-time reconstruction (MRAgent) is more flexible but expensive at inference time. An ideal system might combine both: maintain write-time links as a first-pass retrieval and fall back to read-time reconstruction when the first pass is insufficient.

### Paper 2: CraniMem — Cranial Inspired Gated and Bounded Memory for Agentic Systems

- **Authors:** Pearl Mody, Mihir Panchal, Rishit Kar, Kiran Bhowmick, Ruhina Karani
- **Year:** 2026
- **Link:** https://arxiv.org/abs/2603.15642

**Contributions:**
- Proposes a **neurocognitively motivated memory architecture** — explicitly modeled on human memory systems (sensory memory → short-term/working memory → long-term memory with consolidation).
- **Goal-conditioned gating:** Not all experiences are equally worth remembering. CraniMem uses a gating mechanism that scores new information by its **utility** relative to the agent's current goals. Low-utility information is discarded immediately (analogous to sensory memory filtering), while high-utility information progresses to the bounded episodic buffer.
- **Bounded episodic buffer** (near-term continuity): A fixed-size buffer that maintains the last N turns of interaction for coherent short-term context. When full, older items are either consolidated into the long-term knowledge graph or pruned.
- **Structured long-term knowledge graph** (durable semantic recall): After consolidation, high-utility traces are stored in a structured knowledge graph — not as flat records but as typed relationships (e.g., "Alice [prefers] coffee", "task_X [depends_on] task_Y").
- **Scheduled consolidation loop:** A periodic process that replays high-utility traces from the episodic buffer into the knowledge graph, then prunes low-utility items. This keeps memory growth bounded and reduces interference between stored items.

**Relation to main paper:** CraniMem addresses a gap that both MRAgent and A-MEM leave open: **memory maintenance and boundedness**. MRAgent has no maintenance. A-MEM has write-time linking but no explicit pruning or consolidation. CraniMem explicitly handles the problem of **memory growth management** — it has a bounded working memory and a scheduled consolidation process that prevents unbounded growth while preserving high-value information. This is a crucial practical concern that neither MRAgent nor A-MEM addresses.

**Why it matters:** The neurocognitive inspiration gives CraniMem a principled answer to a question the other systems ignore: **what should be forgotten?** Current systems either remember everything (MemGPT, unbounded growth) or rely on simple recency-based eviction (most practical deployments). CraniMem's utility-based gating and consolidation is a more principled approach. It also introduces important concepts: goal-conditioned retention, consolidation scheduling, and bounded working memory — all of which are missing from the current agent memory design space.

## Current Understanding

Day 3 adds a **new dimension** to the agent memory map. The first two days established:

1. The **four-module framework** (representation / extraction / retrieval / maintenance) — a shared analytical vocabulary (Day 1).
2. **Two foundational concrete paradigms**: OS paging (MemGPT) and database update (MemoryBank), plus enterprise infrastructure (Oracle) (Day 2).

Today adds **three systems that move beyond static retrieval**:

- **MRAgent (Graph Memory):** Memory is not retrieved — it is **reconstructed** through LLM-guided graph traversal. The key insight: static one-shot retrieval misses associative connections. The cost: higher latency and combinatorial explosion risk.
- **A-MEM (Agentic Memory):** Memory is organized by the **LLM itself** at write-time, building an interconnected knowledge network through LLM-guided linking. The key design axis: **write-time vs. read-time graph construction**, a tradeoff that depends on whether you optimize for recall latency (write-time) or retrieval flexibility (read-time).
- **CraniMem (Gated & Bounded Memory):** Memory is **bounded, gated by goal-utility, and periodically consolidated**. The key contribution: principled forgetting. Existing systems accumulate everything; CraniMem actively decides what to keep and what to discard, controlled by the agent's goals.

**The emerging picture:** There is no single "right" agent memory architecture. The design space has at least three important axes:

| Axis | Options |
|------|---------|
| **Representation** | Flat records / Topic documents / Knowledge graph / Cue-Tag-Content graph |
| **Access pattern** | Static retrieval / Write-time graph building / Read-time graph reconstruction / Gated buffer |
| **Maintenance** | Append-only / Similarity-based update / LLM-guided linking / Goal-utility consolidation |

The open challenge: can these approaches be **unified** into a single architecture where the right representation, access pattern, and maintenance strategy are selected based on the agent's current workload?

### Key Concepts

- **Associative memory graph** — memory structured as interconnected nodes (cues, tags, content) enabling path-based traversal
- **Active reconstruction** — LLM-guided iterative memory exploration with pruning, as opposed to static one-shot retrieval
- **Cue-Tag-Content (CTC) graph** — three-layer graph structure with fine-grained cues, semantic tags as bridges, and content as leaves
- **LLM-as-search-controller** — the LLM directs memory traversal by scoring path utility at each expansion step
- **Write-time vs. read-time graph construction** — design axis: build connections when storing (A-MEM) vs. when retrieving (MRAgent)
- **Zettelkasten memory** — atomic memory notes with LLM-generated cross-references and linking
- **Goal-conditioned gating** — filter new experiences by utility relative to agent goals
- **Bounded episodic buffer** — fixed-size short-term memory for near-term continuity
- **Scheduled consolidation loop** — periodic replay of high-utility traces from episodic to long-term memory
- **Utility-tagged pruning** — discard low-utility memories to keep memory growth bounded
- **Neurocognitive memory inspiration** — designing agent memory after human memory architecture (sensory → short-term → long-term with consolidation)

## Open Questions

1. **Write-time vs. read-time graph construction: which is better?** A-MEM builds connections when storing memories (cheap read, expensive write). MRAgent reconstructs when retrieving (expensive read, flexible write). Is there a principled way to decide which approach — or a hybrid — is optimal for a given workload?

2. **Can the associative reconstruction paradigm generalize beyond conversation tasks?** MRAgent is evaluated on long-conversation recall. Does it help for agent tasks involving tool use, code generation, or long-horizon planning — where the "memory" includes procedural knowledge, API documentation, and execution traces?

3. **How should bounded memory interact with the agent's goals?** CraniMem uses goal-conditioned gating, but how should goals be represented and updated? Do goals change over the agent's lifetime, and if so, should previously consolidated memories be re-evaluated for utility under new goals?

4. **Is the LLM-as-search-controller pattern reliable?** MRAgent's reconstruction depends on the LLM making good pruning decisions. What happens when the LLM prematurely prunes the correct branch? Can we design recovery mechanisms (backtracking with diversity)?

5. **Do graph-based memories scale?** A-MEM and MRAgent operate at 10K-record scales. Real agent deployments could involve millions of records over weeks of interaction. Does the graph approach break down at scale, or can it be made to scale through partitioning?

6. **Can we unify write-time and read-time graph construction?** An ideal system might maintain lightweight write-time links for fast first-pass retrieval, then fall back to read-time reconstruction when the first pass fails (low confidence in retrieved results). How would such a hybrid system be designed?

7. **Is goal-conditioned gating a form of meta-learning?** CraniMem's gating adapts what is remembered based on agent goals. Could this be framed as a meta-learning problem where the agent learns what types of information are worth remembering over its lifetime?

8. **How should memory maintenance and retrieval be jointly optimized?** Current work treats maintenance (CraniMem's consolidation) and retrieval (MRAgent's reconstruction) as separate modules. Is there a benefit to making them aware of each other — e.g., a consolidator that knows which retrieval strategies are most effective?

## Possible Thesis Ideas

- **Unified graph memory with adaptive construction mode** — A single memory system that maintains lightweight write-time links for fast retrieval (A-MEM-style) but switches to read-time reconstruction (MRAgent-style) when retrieval confidence is low. The controller decides which mode to use based on query complexity, task criticality, and latency budget.

- **Goal-adaptive bounded memory for lifelong agents** — Extend CraniMem's gating to handle evolving goals: as the agent's objectives change over time, re-evaluate previously consolidated memories for continued utility. This would require a feedback loop between goal update and memory re-consolidation.

- **LLM-guided memory maintenance as a learned skill** — Train a specialized model (or fine-tune a small LLM) whose job is memory maintenance: detecting contradictions, linking related memories, pruning low-utility content, and scheduling consolidation. This could run as a background process alongside the main agent, similar to a garbage collector in a runtime system.

- **Neurocognitive agent memory: from inspiration to evaluation** — CraniMem's neurocognitive approach is promising but lacks rigorous evaluation against biological memory phenomena. Could we design agent memory benchmarks that test known human memory effects (primacy/recency, spacing effect, interference, retrieval-induced forgetting)? A systematic evaluation of whether neurocognitive mechanisms actually improve agent memory would be valuable.
