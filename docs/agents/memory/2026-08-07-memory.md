## Journey Recap

### Day 1 — The Four-Module Framework
**Survey**: Zhou et al. (2026) decomposed agent memory into representation/storage, extraction, retrieval/routing, and maintenance, and evaluated 12 systems across 5 workload types.
**Insight**: There is no single best architecture — the right memory design depends on *workload-memory alignment* (fact precision vs. contextual narrative, static vs. dynamic facts, single- vs. cross-session). The semantic/episodic distinction from cognitive science is a key design axis.

### Day 2 — The OS-Inspired Concrete System
**Main**: MemGPT — virtual context management: two-tier memory (main context = RAM, external context = disk), paging via function calls, OS interrupts for overflow/timeout.
**Related**: MemoryBank (append + similarity-based update → contrast: mutable vs. append-only), Oracle (enterprise substrate: concurrency, ACID, access control).
**Insight**: The OS analogy is powerful but has a fork: does the *LLM* manage memory (MemGPT) or does the *backend service* (Oracle)? And append-only vs. mutable is a fundamental design split.

### Day 3 — Memory Is Reconstructed, Not Retrieved
**Main**: MRAgent — Cue-Tag-Content (CTC) graph memory + LLM-guided active reconstruction with iterative pruning, replacing one-shot retrieve-then-reason.
**Related**: A-MEM (agentic memory, Zettelkasten-style write-time linking), CraniMem (neurocognitive gated, bounded, consolidated memory).
**Insight**: A new design axis — write-time vs. read-time graph construction, and static retrieval vs. dynamic reconstruction. Richer memory structures enable associative recall but introduce new costs and failure modes.

### Day 4 — The Trust Axis: Poisoning, Non-Malleable Defenses, and Benchmarks
**Main**: Memory poisoning — four write channels (user input, tool output, retrieved content, self-generated traces), nine structural vulnerabilities, six attack classes, MPBench benchmark.
**Related**: TMA-NM defense (write-time origin-bound, non-malleable authority; content/lineage defenses provably unsound under laundering), LoCoMo (long-term conversational memory benchmark; all systems lag human recall).
**Insight**: Every architecture from Days 1–3 has **no trust boundary**. Memory security and memory architecture are coupled: richer/aggressive memory = larger attack surface.

## Unified Understanding

Agent memory is a **stack of coupled design decisions**, not a single feature:

```
┌─────────────────────────────────────────────────────┐
│ 4. TRUST  (Day 4) — write-time origin binding,      │
│    non-malleable provenance, poisoning threat model │
├─────────────────────────────────────────────────────┤
│ 3. MAINTENANCE — append-only vs. mutable,           │
│    consolidation, pruning, contradiction handling   │
├─────────────────────────────────────────────────────┤
│ 2. RETRIEVAL — static similarity vs. agentic        │
│    reconstruction vs. gated/bounded access          │
├─────────────────────────────────────────────────────┤
│ 1. REPRESENTATION — flat records, topic documents,  │
│    graphs, episodic vs. semantic tiers              │
└─────────────────────────────────────────────────────┘
```

Four cross-cutting findings:

1. **There is no universal memory architecture.** The Zhou 2026 survey's workload-memory alignment principle is the organizing law: representation/retrieval choices should be driven by workload characteristics (fact precision, dynamics, session structure). Any thesis proposing "the right memory" without specifying workload is incomplete.

2. **Memory quality is bounded by evaluation and trust, not just architecture.** LoCoMo shows even the best long-context + RAG configurations lag human recall; MPBench shows aggressive memory is exploitable. The two evaluation axes (quality × security) are not yet measured on the same system.

3. **Memory and tool use share a composition-safety lesson.** ChainCaps (tool-use topic): individually-safe tool calls compose into unsafe workflows. Memory poisoning: individually-innocent memory writes compose into poisoned beliefs. Both resist single-step defenses — safety is a property of the *pipeline*, requiring provenance and authority tracking across transformations (summarization, graph reconstruction, consolidation are all laundering opportunities).

4. **The security axis is the least explored.** Days 1–3 systems all assume stored content is trustworthy. The TMA-NM result (write-time origin-bound authority is *necessary* for sound defense) is a design principle every future memory architecture must respect — but integrating non-malleable provenance into graph/agentic memory without losing associative benefits is open.

## Key Concepts (consolidated)

- Four-module memory framework: representation, extraction, retrieval, maintenance
- Workload-memory alignment principle
- Semantic vs. episodic memory for agents
- Virtual context management / OS-inspired memory hierarchy (MemGPT)
- Two-tier memory: main context (RAM) + external context (disk); paging via function calls
- Append-only vs. mutable memory
- Enterprise memory substrate (concurrency, ACID, access control)
- Associative graph memory (Cue-Tag-Content), write-time vs. read-time construction
- Active reconstruction: LLM-guided iterative traversal with pruning
- Zettelkasten-style agentic memory (A-MEM)
- Neurocognitive gated/bounded memory with consolidation (CraniMem)
- Memory poisoning: 4 write channels × 6 attack classes (MPBench)
- Aggressive-memory exploitability — richer memory = larger attack surface
- Laundering channels: agent summarization, trusted-tool echo, manufactured corroboration
- Origin-bound authority + non-malleable IFC (TMA-NM, machine-checked)
- LoCoMo long-term memory benchmark (300 turns, 35 sessions)
- Composition safety for memory (parallel to tool-composition safety)

## Open Questions (most important for the frontier)

1. **Can non-malleable provenance be added to graph/agentic memory without destroying its associative benefits?** TMA-NM was tested on simple stores; MRAgent-style reconstruction and CraniMem-style consolidation each move/transform content, and each move is a laundering opportunity.
2. **Where is the utility/security sweet spot for memory write policy?** More aggressive memory is more exploitable; minimal memory is safest but useless. Is there a principled way to trade utility against learned poisoning risk?
3. **Is the counterfactual/episodic gap fundamental?** All systems lag human long-term recall on LoCoMo — is the bottleneck representation, retrieval, consolidation, or something else entirely?
4. **What does a unified memory benchmark (quality × security) look like?** LoCoMo measures recall, MPBench measures attack success. No benchmark scores recall *under adversarial memory pressure*.
5. **Do shared memory stores (multi-agent, enterprise) create new attack surfaces?** If agent A poisons a shared store, does agent B inherit the poisoned belief?

## Possible Thesis Ideas (refined)

1. **Trust-aware memory architecture** — integrate write-time origin-bound provenance (TMA-NM's T2 principle) into a graph/agentic memory (MRAgent/A-MEM style), with retrieval filtered by relevance AND trust. Directly combines architecture (Days 1–3) with security (Day 4).
2. **Unified memory benchmark: quality × security** — poison a fraction of memory entries and measure both attack success and legitimate recall degradation. First benchmark scoring both axes would become a reference point.
3. **Consolidation-aware provenance propagation** — formalize how origin authority propagates through lossy consolidation/summarization; design a provenance-aware consolidator that keeps authority intact (attacks the "agent's own summarization" laundering channel from the defense side).
4. **Adaptive memory write policy under threat** — learn per-task, per-source how much to trust-and-write vs. filter-and-discard, trading utility against a learned poisoning-risk estimate.
5. **Workload-aware memory architecture selector** — given a task description, predict the best (representation, retrieval, maintenance) combination; makes the Zhou 2026 framework operational.
