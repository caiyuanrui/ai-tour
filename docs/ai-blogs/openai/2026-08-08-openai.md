### Core Problem

For voice AI, knowing when to speak is harder than it sounds. Human speakers hand off in a fraction of a second, but previous voice systems could not keep up: they used a turn-based architecture gated by tiny "turn detector" models that had to guess when the user was done. Guess too soon → the user gets cut off; guess too late → the response feels sluggish. Only after the detector decided could the much larger LLM begin working. This sequencing (STT → LLM → TTS, each as discrete audio blobs) added latency and threw away cues like tone and pacing.

### Technical Approach

GPT-Live, OpenAI's third-generation voice system, removes the turn detector from the audio path entirely:

- **Full-duplex voice model** that listens and speaks simultaneously — the model itself controls the conversation, so no separate detector is needed.
- **Two-model architecture**: the fast voice model sustains the media loop, while deeper reasoning/tool use is delegated asynchronously to frontier models (e.g. GPT-5.5) without interrupting the flow of conversation.
- **Streaming stateful inference**: incoming audio streams into the model and outbound speech streams back; a new stateful inference system is built for continuous conversation rather than request-response.
- **Dedicated media fast path**: audio moves between client and voice model on a dedicated path, separated from application/business logic behind an asynchronous RPC boundary. A slow tool call can delay its own result but cannot stall the media flow.
- **Go rewrite**: media frontend and inference logic rewritten from Python asyncio into Go — new system's p95 frame delivery matches the old system's p50.
- **WebRTC transport**: survives packet loss, clock drift, and connection changes; can stretch audio to prevent gaps and accelerate playback to catch back up to real time.

### Key Engineering Details

- **Stateful inference handoff**: voice sessions stay open long, context grows, and model instances spin up/down. On transition, they warm a replacement instance, prefill it with current session context, run inference against both in parallel, and cut over when ready.
- **Compaction as a managed transition**: when context exceeds the limit, compaction reduces it — but compaction invalidates the KV cache (rebuilt state requires a new prefill). So compaction is treated like a handoff: the original instance keeps chatting while the new context is prepared, then switch over without media interruption.
- **Delegation latency budget**: the full delegation loop (routing, prompt processing, inference, tool calls) counts against responsiveness. At session start, the frontier model's inference session is created and prefilled with conversation context; stable session affinity + prompt caching keep it fast.
- **Discrete turns from continuous speech**: the app server segments overlapping speech into messages using partial transcripts + timing signals; keeps a *speculative* view (UI, mutable) and an *authoritative* record (analytics/safety, finalized).
- **WARP protocol**: WebRTC Abridged Roundtrip Protocol reduces media/data startup from six network round trips to one — piggybacking DTLS over ICE (SPED), DTLS 1.3, pre-negotiated SCTP (SNAP), pre-negotiated data channels. Plus "Instant Connect" takes the SDP exchange off the critical path — a session now starts with a single UDP packet. Open specs being advanced through IETF TSVWG; support already in libwebrtc and Pion.
- **Silent production testing**: routed a small, growing share of real ChatGPT Voice traffic to the new system in read-only shadow mode. Lessons: capacity ≠ GPU throughput (CPU-side stream handlers/queues saturate first); geography is first-order (distant routing adds startup + streaming delay); long sessions expose memory/persistence pressure, reconnect compaction, shutdown-handshake races that short load tests never show.

### Why It Matters (vs. papers)

Papers describe speech-to-speech *model* architectures, but the blog shows the hard part is the **system**: turn-taking is an infrastructure decision, not a model property. KV-cache invalidation during compaction, instance handoff with parallel prefilling, transport round-trip counts, and "responsiveness budgets" spanning routing → prompt → inference → tool calls are engineering realities that never appear in a model card. This is the clearest example yet of frontier labs treating realtime interaction as an end-to-end systems problem.

### Connection to Research Map

- **llm-systems / inference-serving & kv-cache**: streaming stateful inference; compaction-invalidates-KV-cache → handoff-with-rebuild pattern; prompt caching.
- **llm-systems / agent-runtime**: two-model architecture (fast voice model + delegated frontier model) is effectively an agent runtime with a hard latency budget; asynchronous RPC boundary between media path and tool/agent logic.
- **agents / tool-use & planning**: delegation must be *pre-warmed* (session affinity, prefilled context) to be usable mid-conversation — a practical lesson for agent orchestration.
- **multimodal / vla**: full-duplex audio interaction is a realtime perception-action loop; the WARP/Instant Connect transport work generalizes to any realtime multimodal agent.

## Related Posts

### Post 1 — How enabling two settings tripled our scores on the ARC-AGI-3 benchmark

- **Metadata**: OpenAI · 2026-07-29 · https://openai.com/index/how-two-settings-tripled-our-arc-agi-3-scores/
- **What it says**: GPT-5.6 Sol scored just 7.8% (GPT-5.5: 0.4%) on ARC-AGI-3, a benchmark of 2D puzzle games where agents explore unfamiliar games and infer rules without instructions. Investigation revealed the model was not the problem — the *harness* was. (1) The official harness discarded all private reasoning after each action, so the model had to re-figure-out the game from scratch every turn. (2) It used rolling truncation (oldest messages dropped past ~175K), so the model also lost memory of its past actions. Switching to the Responses API with **retained reasoning** + **compaction** (their production ChatGPT/Codex setup) tripled the score (13.3% → 38.3% on the public set; average human ≈ 48%) while cutting output tokens 6×.
- **Relation to main post**: both posts are about *statefulness*. GPT-Live's compaction-as-handoff is the systems answer to long-horizon context; the ARC post shows the same idea (retain reasoning, compact instead of truncate) tripling agent performance on a benchmark. Together they argue that "memory of past thinking" is a first-class engineering primitive, not an eval detail.

### Post 2 — How GPT-5.6 fuses frontier intelligence with frontier efficiency

- **Metadata**: OpenAI · 2026-07-29 · https://openai.com/index/gpt-5-6-frontier-intelligence-efficiency/
- **What it says**: GPT-5.6 family (Sol / Terra / Luna) is trained for more *work per token*. Efficiency comes from three layers: (1) **inference** — load balancing across geography/cluster/instance, GPT-5.6 Sol autonomously rewriting production kernels in Triton/Gluon (20% end-to-end serving cost reduction, validated with the open-source FpSan sanitizer), speculative decoding with a self-designed draft model (+15% token-generation efficiency); (2) **agentic harness** (a Rust orchestration layer for Codex/ChatGPT Work) — deferred discovery of tools/MCP integrations/plugins to avoid context bloat, tool output capped at 10K tokens, append-only history + deterministic tool order to preserve exact prefixes for prompt caching; (3) **model** — optimized in training for direct task paths.
- **Relation to main post**: GPT-Live's delegation path (prefilled sessions, prompt caching, session affinity) is exactly the harness/inference engineering this post generalizes. Both show OpenAI using its own frontier models (Sol in Codex) to optimize the stack that serves them — a closed loop that papers rarely describe.

## Current Understanding

OpenAI's current engineering center of gravity is **realtime, stateful, efficient agentic systems**. Three posts read as one coherent story:

1. **Statefulness is a system property**: retaining reasoning, compaction-as-handoff, and KV-cache-aware context management turn out to be worth 3× benchmark scores (ARC-AGI-3) and are what make continuous voice conversation (GPT-Live) possible. "Memory of past thinking" is engineered, not just prompted.
2. **Realtime means the whole path**: from transport protocols (WARP: 6 → 1 round trips) to pre-warmed delegation sessions, latency is a budget owned end-to-end; capacity planning must count CPU-side stream handling, not just GPU throughput.
3. **Self-optimizing stacks**: GPT-5.6 Sol autonomously rewrites kernels, tunes load balancing, and designs its own speculative decoder — the frontier model is now a tool in the inference optimization loop. Efficiency (20% serving cost cuts, 15% token-gen gains, work-per-token training) is treated as a product feature.

## Open Questions

- How does compaction decide *what* to keep vs. summarize, and how much task-relevant information is lost in long agent sessions? (ARC post shows compaction >> truncation, but where is the failure mode?)
- GPT-Live delegates to frontier models, but when should the voice model decide *not* to delegate? What is the cost/benefit policy and how is it learned?
- Is there a principled theory of "responsiveness budgets" for multi-model agent stacks, or is it all heuristic engineering?
- How far does self-optimization (model-written kernels, self-designed speculators) generalize beyond OpenAI's controlled stack — is this a research direction or a moat?
- The ARC-AGI-3 result is a cautionary tale for benchmark comparisons: how many published agent-benchmark gaps are actually harness artifacts?
